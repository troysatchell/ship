# System Patterns — Architecture Facts for Auditing

*How the system is built, filtered to what the audit needs. `.claude/CLAUDE.md` and `docs/` are the full picture; this file records what we verified ourselves and where our findings disagree with the docs.*

## Verified architecture (orientation, 2026-07-27)

- **Monorepo:** pnpm workspaces — `web/` (React 18 + Vite 6 + TipTap), `api/` (Express 4), `shared/` (types). Node ≥20.
- **DB layer:** raw `pg` Pool (`api/src/db/client.ts`, max 20/10 conns, 30s statement timeout) — inline parameterized SQL in route files, no ORM. Schema: `api/src/db/schema.sql` + **42 migration files** (verified via DB-1; `schema_migrations` tracks applied).
- **Unified `documents` table:** `document_type` enum (10 types), `content` JSONB (TipTap), `yjs_state` BYTEA, `properties` JSONB (GIN-indexed), `parent_id` self-FK with circular-parent trigger, soft delete via `archived_at`/`deleted_at`.
- **Associations:** `document_associations` junction (parent / project / sprint / program). **Docs discrepancy — RESOLVED 2026-07-28:** `.claude/CLAUDE.md` claimed `program_id`/`project_id` still existed and credited 027 with dropping only `sprint_id`. Verified against the migration files: **027 drops `sprint_id` AND `project_id`; 029 drops `program_id`** — all three gone from `documents`. CLAUDE.md corrected in `56ae2aa`. The trap that caused it: `sprint_iterations.sprint_id` (`schema.sql:272`) is a live column on a *different* table. Because of DB-1 a given database may not have run 027/029, so `\d documents` stays the authority.
- **Routing:** ~33 route modules mounted in `api/src/app.ts:173-237` under `/api/*`; helmet + session cookies + csrf-sync + express-rate-limit (`loginLimiter` on login). Swagger at `/api/docs/`.
- **Realtime:** WebSocket collab at `/collaboration/{docType}:{docId}` (`api/src/collaboration/`), Yjs state persisted to Postgres. **Verified 2026-07-27:** session is validated only at the WS *upgrade* (`collaboration/index.ts:659`), never per-message — so a revoked/expired session keeps writing on an open socket (ERR-2). Doc load (`getOrCreateDoc`) reads `yjs_state`, falling back to converting `content` JSON; an undecodable `yjs_state` produced an *uncaught* lib0 crash in the probe log (ERR-1 boot-crash note — needs a clean repro).
- **Recurring pattern in `api/src/collaboration/index.ts`, verified 2026-07-30 (TRO-284/TRO-285): async work between making something reachable and making it able to respond.** `wss.on('connection')` is `async` and does a database round trip before the socket is fully wired up; anything registered *after* that `await` is exposed to whatever arrives in the gap. Found three times, independently: **ERR-10** (TRO-276, fixed) — the `'error'` listener was attached after the `await`, so a malformed frame in the gap escaped to the process; fixed by moving it to the first statement. **ERR-11** (TRO-284, fixed) — the `'message'` listener was attached after the `await`, so a client's sync step 1 landed with nothing listening and was silently dropped (`EventEmitter` discards an unlistened event); fixed by registering a bounded buffering listener before the `await` and draining it once the doc loads. **ERR-12** (TRO-285, fixed) — `getOrCreateDoc()` published the new `Y.Doc` into the shared `docs` map *before* awaiting its own load, so a second connection in the gap got the doc cached-but-empty; fixed by making the map hold the *load promise*, not the doc, so every concurrent caller converges on one fully-loaded result. The next change to this file's connection handler should treat "what happens to a frame that arrives before my `await` resolves" as a required question, not an edge case — it has produced a real, independently-rediscovered bug three times running.

## Index reality (db-query audit foundation)

Present on `documents`: workspace_id, parent_id, document_type, GIN(properties), visibility combos, partial archived/deleted, `(workspace_id, document_type)` active partial, conversion partials, person user_id expression index.
**Absent:** `ticket_number`, `created_by`, `updated_at`.

## Audit-relevant pattern observations

- Web `tsconfig.json` does **not** extend the root config — missing `noUncheckedIndexedAccess`, `noImplicitReturns`, `noFallthroughCasesInSwitch` that api/shared inherit. (Type-safety lead TS-candidate #1.)
- Web has 24 explicit `any` but **433 `as` assertions** — the type-safety story here is assertions, not `any`.
- Code splitting exists only for 13 document-tab components (`web/src/lib/document-tabs.tsx`); no route-level lazy loading, no `manualChunks`, no analyzer installed.
- API vitest declares v8 coverage but `@vitest/coverage-v8` is not installed — coverage tooling is broken as shipped. Root `pnpm test` runs api only; web's 16 unit test files are never run by it.
- E2E: 71 spec files / ~866 tests, per-worker Postgres testcontainers + `vite preview` (dev server documented to blow up memory). Retries 2 CI / 1 local — flakiness measurement must track first-attempt results.
- A11y: `e2e/accessibility*.spec.ts` run AxeBuilder scans with WCAG-numbered phases; USWDS + Radix primitives supply baseline semantics. **Refined 2026-07-27:** those specs assert only `impact === 'critical'`, so Serious/Moderate/Minor pass by construction. The independent axe superset (pages + interactive states) found 2 Critical + 3 Serious the specs and Lighthouse (95–100) both miss — see `audit/a11y/baseline.md` (A11Y-1 sidebar `role="tree"`, A11Y-2 editor `aria-expanded`, A11Y-3 /my-week contrast). A seeded user with an overdue action item gets an "Action Items" `role=dialog` that auto-opens on every nav and traps focus (Escape closes it) — dismiss it before scanning.

## Deploy path (verified 2026-07-28, reading the artifacts not deploying)

- **The Docker image is API-only and expects a pre-built artifact.** `Dockerfile:22-23` copies `shared/dist/` and `api/dist/` — both gitignored (`.gitignore:6`) and untracked. `.dockerignore` states the assumption outright. It is built for the AWS flow where `scripts/deploy.sh` compiles locally and then `docker build` packages the result, so it **cannot build from a fresh clone**. There is no `COPY web/` and no web build step, so the image serves no UI. Single stage, `FROM public.ecr.aws/docker/library/node:20-slim` (ECR mirror — Docker Hub is blocked in government environments).
- **Migrations run on every container start** — `Dockerfile:35` is `node dist/db/migrate.js && node dist/index.js`. Combined with DB-1 (migrate exits 0 while skipping 32 files), the `&&` proceeds and the API starts against a partially-migrated database having printed success.
- **SSL config is inconsistent across the three DB entry points** (DB-11 / `TRO-240`). `migrate.ts:32` and `seed.ts:44` set `ssl: { rejectUnauthorized: false }` in production; **`client.ts` — the main application pool — sets none.** Dormant on AWS (Aurora is in-VPC); breaks against any TLS-requiring managed Postgres, and the `migrate &&` ordering makes the failure read as a database problem rather than a client-config one.
- **The app assumes same-origin serving.** Session cookie is `sameSite: 'strict'` (`middleware/auth.ts:217`, `routes/auth.ts:188`, deliberate for a government app); the collab WS URL is built from `window.location.host` (`Editor.tsx:334`); `VITE_API_URL` defaults to `''` (`Editor.tsx:330`). CloudFront provides that today by serving the SPA and proxying `/api/*` + `/collaboration`. **Any split frontend/API deployment breaks login and collaboration silently.**

## House rules that constrain fixes (from repo CLAUDE.md — follow them)

Everything is a document (no new content tables) · reuse the shared `Editor` · migrations only, never edit schema.sql for existing tables · all API routes registered with OpenAPI (`/ship-openapi-endpoints`) · philosophy review via `/ship-philosophy-reviewer` · never `git commit --no-verify` · e2e via `/e2e-test-runner`, never raw `pnpm test:e2e`.
