# Ship frontend

Read this before touching `web/`. It is the domain layer the factory's generic agent contract
does not carry: the contract tells you how to prove a fix; this tells you what is true about this
frontend.

## Stack, as it actually is

| | |
|---|---|
| Framework | React **18.3**, TypeScript 5.7, **Vite 6** |
| Routing | `react-router-dom` 7 |
| Server state | `@tanstack/react-query` (+ persist-client, idb-keyval offline cache) |
| Editor | TipTap 2 (`@tiptap/react`) with **Yjs** collaboration + `y-websocket`, `y-indexeddb` |
| Primitives | Radix (`dialog`, `popover`, `tooltip`), `cmdk`, `@dnd-kit`, `tippy.js` |
| Styling | Tailwind + `clsx`/`tailwind-merge`; **no** component library |
| Icons | `@uswds/uswds` sprite via `vite-plugin-svgr`; types generated by `pnpm --filter @ship/web generate:icon-types` |
| Tests | Vitest + **jsdom** + Testing Library. Setup is one line: `@testing-library/jest-dom` |

There is **no ESLint config in this repo** (finding TS-6). No package defines a `lint` script, so
`pnpm lint` recurses, matches nothing, and exits 0. Do not treat a clean `pnpm lint` as a signal,
and do not add one as a drive-by.

## Non-negotiable architecture

These come from `docs/document-model-conventions.md` and are enforced by
`/ship-philosophy-reviewer`. Violating them fails review regardless of code quality.

1. **4-panel layout, always.** Icon Rail (48px) → Contextual Sidebar (224px) → Main Content
   (flex-1) → Properties Sidebar (256px). All four always visible. Do not add a fifth panel or
   make one conditional.
2. **One `Editor`.** `web/src/components/Editor.tsx` serves every document type. Type differences
   live in the **properties sidebar** (`web/src/components/sidebars/PropertiesPanel.tsx`) and in
   the sidebar's item list — never in a second editor. No `IssueEditor`, no `WikiEditor`.
3. **`"Untitled"` exactly.** Every new document of every type. `Editor` matches that literal
   string to apply placeholder styling; `"Untitled Issue"` silently breaks it.
4. **No new content tables.** Everything is a document. If a change seems to need one, that is a
   design conversation, not a ticket.

## Tailwind palette — the contrast values are load-bearing

`web/tailwind.config.js` carries a deliberately narrow dark palette, and two of its entries have
WCAG arithmetic in the comments: `muted` was moved from `#737373` (4.09:1 — failing) to `#8a8a8a`
(5.1:1). If you introduce a color, compute its contrast against `background: #0d0d0d` and put the
ratio in the comment the way the existing entries do. A new hex with no ratio beside it is how the
palette regresses back under 4.5:1.

## Accessibility: what you can and cannot conclude

The standing example lives at `web/src/components/DocumentTreeItem.tsx:70` — an element with
`role="treeitem"`, `aria-expanded`, and `aria-selected`, and **no `tabIndex` and no `onKeyDown`**
anywhere in the file (verified 2026-07-29 by grep). An ARIA role that implies interaction without
keyboard handling is not a labelling bug; the element is unreachable.

Rules that follow:

- **Prefer native semantics.** A `<ul>`/`<li>` with real `<a>`/`<button>` children needs no ARIA
  and gets focus, keyboard, and announcement for free. Reach for `role=` only when no native
  element expresses the pattern — and then you own focus management, `tabIndex`, arrow-key
  handling, and `aria-activedescendant` for the whole widget.
- **axe tells you about contracts, not about speech.** It reports names, roles, landmarks, and
  contrast. It cannot tell you what a screen reader says. A11Y-1 was written up as *"announced
  incorrectly"* from an axe rule; a human running VoiceOver found the titles are **not announced at
  all** — a worse defect. Any claim about what is announced requires a human. That is escalation
  gate 5 in the factory (`ship-factory/references/escalation.md`).
- **A screenshot is not an a11y check** and neither is a Lighthouse score. Lighthouse 100 coexists
  with unreachable controls; the audit report has a section titled exactly that
  (`audit/AUDIT_REPORT.md` — "The headline: Lighthouse ≠ conformance").
- **Deleting an ARIA role is a user-visible change.** The recommended A11Y-1 fix is subtraction —
  drop `role="tree"`/`role="treeitem"` and let list semantics work. That changes product
  behaviour, so it stops for the maintainer rather than shipping on an agent's judgement.

## Editor and collaboration hazards

Document content exists in **two** places: TipTap JSON in `documents.content` and the binary CRDT
in `documents.yjs_state`. The collaboration server (`api/src/collaboration/index.ts`) owns
`yjs_state` for any doc with a live session at `/collaboration/{docType}:{docId}`.

- Writing `content` directly while a session is open does **not** update the Yjs doc; the next sync
  overwrites your write. Go through the editor or the collaboration path.
- TipTap extensions live in `web/src/components/editor/` and several have unit tests
  (`MentionExtension.test.ts`, `DetailsExtension.test.ts`, `DragHandle.test.ts`). Those tests
  exercise extension logic in isolation — they are the cheapest place to add a regression test for
  an editor bug, and they run in the gate.

## Testing — where a frontend regression test has to live

**`pnpm test` at the repo root runs api only.** Web is `pnpm --filter @ship/web test`. Missing that
is how a "tests pass" claim gets made about a suite that never ran.

- Web has **16 test files** (`web/src/**/*.test.ts?(x)`), jsdom + Testing Library, no MSW — network
  is stubbed per test.
- **`audit/factory/quarantine.json` currently lists `knownFailing: 0` for both api and web.** The
  13 web failures that once lived there were TEST-1 / TRO-223 and were fixed on 2026-07-29, and
  their entries deleted as the file's own comment required. Both suites are green on arrival, which
  raises the bar rather than lowering it: **any failure the gate sees now is new and yours.** The
  gate still compares failure *identities* against that baseline, so quarantining is a mechanism,
  not a fixed list. Never add an entry to make your branch green; removing one you genuinely fixed
  is the only legitimate edit.
- **Playwright specs in `e2e/` are not run by the factory gate** — neither vitest config includes
  them (`api` pins `src/**/*.test.ts`; `web`'s root is `web/`). A regression test that exists only
  as an e2e spec will satisfy the gate's "regression test added" check while never executing. Put
  the regression test in a vitest file; add the e2e spec as well if the flow deserves it. See
  `/ship-qa`.
- Query by **role and accessible name** (`getByRole('button', { name: /save/i })`), not by class or
  test id. A test that passes through the accessibility tree fails when the component becomes
  unreachable — which is the defect class this codebase actually has.

## Bundle size

Measure, do not estimate: `/bundle-audit compare <label>` against the `audit-baseline` tag.

One conditions trap, from the audit methodology: **run the build from `web/`**, because Tailwind's
`content` globs resolve against the CWD. Building from the repo root changes what Tailwind sees and
the CSS number stops being comparable to the baseline.

BUN-1 and BUN-2/3/4/6 share one root cause — they are one fix and one branch, not five.

## Reporting a frontend claim

Mark **observed** vs **derived**, and state the configuration. Specifically:

- "axe reports X" is observed. "Screen readers say Y" is derived unless a human listened.
- A jsdom test passing is evidence about logic, not about layout, focus order, or paint.
- Give `file:line` for the root cause. `DocumentTreeItem.tsx:70`, not "the sidebar".
