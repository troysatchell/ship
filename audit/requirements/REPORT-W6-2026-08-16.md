## Coverage and limitations

- **This is a targeted delta sweep, not a full re-verification of all 79 rows.** Per the sweep's own scoping instruction, re-tracing prioritized: (a) all 29 prior MISSING/PARTIAL rows, (b) rows whose evidence files were touched by the 21 PRs merged since 08-15, and (c) a light spot-check of unrelated VERIFIED rows. 26 rows changed; the other 53 carried forward from 08-15 without independent re-tracing this pass — except that the Phase-4 completeness check (re-opening every citation) ran against **all 79 rows**, which is what surfaced the 7-row labeling defect above and 2 stale line-number citations (see below).
- **No local `pnpm test` / `pnpm type-check` run was performed this sweep.** The main worktree's checked-out `HEAD` was 28 commits behind `origin/main` at sweep start and carried unrelated uncommitted changes (in-progress memory-bank edits, the 08-15 sweep's own never-committed output) — running tests against that stale, dirty tree would not have reflected `origin/main`'s real state, and stashing/resetting it was out of scope for an audit-only sweep with a hard rule against touching anything outside `audit/requirements/` and the config. Every evidence citation and rows W6-R30/R46/R49/R50/R52/R56/R57/R59/R62/R67 instead rely on **GitHub Actions CI results** (per-PR checks and per-push runs on `main`), which exercise the identical `pnpm test`/`pnpm type-check` commands this skill's own `verify:` block names — cited by run ID/SHA, not re-run locally.
- **Live-deploy checks were GET-only and shallow.** `curl` against `https://ship-rr6m.onrender.com/health` and `/developer/apps` (both 200) confirms the service is up and the SPA route doesn't 404 — it does **not** confirm which commit is actually deployed, nor that the React route renders portal content (would need a headless-browser check, not run). W6-R37/R77 are held at `IMPLEMENTED-UNVERIFIED`/`PARTIAL` rather than `VERIFIED` specifically because of this gap.
- **W6-R59 (0% flake over 20 CI runs) is structurally short of its own bar**, not a judgment call: 18 completed `drill-ttfe` CI runs exist as of this sweep (0 failures), 2 short of the named 20-run threshold.
- **2 evidence citations had drifted stale** since 08-15 due to unrelated file changes (a line-number citation in `api/src/platform/api/v1/resources/webhooks.ts` had shifted from 1071 to 578 as the file shrank; `.github/workflows/ci.yml`'s `drill-ttfe` job moved from line 405 to 418) — both corrected in this matrix after the completeness re-check caught them. One dead citation (`.factory/drill-ttfe.log`, a worktree-local scratch path never meant to be a durable citation) was removed from W6-R49/R55's evidence.
- **Ticket-mapping correction, not a new finding:** TRO-400 (PF-201) and TRO-414 (PF-205), both real, Done, pre-08-15 tickets, were mapped to no requirement ID and absent from the 08-15 orphan list — a Phase 2 gap in that sweep, caught and recorded as orphans here (with the correction flagged explicitly) rather than silently fixed.
