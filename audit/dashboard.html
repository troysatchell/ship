2026-07-27 · Category 8 (Terraform / IaC) — complete

Added an 8th category: a Terraform plan review of terraform/. Reality check up front — the config is AWS (Elastic Beanstalk + Aurora Serverless v2 + VPC + CloudFront/S3 + WAF + SSM), not the Render setup the brief assumes, and a live terraform plan can't run without AWS credentials and the SSM-stored S3 state bucket. So blast radius was reasoned statically from the code plus terraform validate, and drift was demonstrated cloud-free with the hashicorp/local provider (clean plan → manual out-of-band edit → plan recreates the files back to declared content).

Six findings, no Criticals but two sharp High foot-guns: TF-1 — the prod Aurora DB and the uploads bucket have no deletion protection; the only guarded resource is the Terraform state bucket. TF-2 — two divergent root configs manage the same infra (the flat root carries WAF + realtime logging that the modular environments/prod path lacks). And TF-3: the pinned Terraform 1.6.0 can't even init anymore — its bundled provider-signing key has expired. The infra is otherwise well-secured (encryption everywhere, private subnets, WAF, SSM SecureString). Report now stands at 68 findings across 8 categories.

2026-07-27 · Group C (error-handling · a11y) + report — complete

Error-handling fault-injection found the two remaining Criticals, both in the collaboration server. ERR-1: when the collab WebSocket is unreachable at load, the editor accepts edits under a "Saved"/"Cached" label, never syncs, and the DB is empty after reload — whole-browser-offline recovers, this specific case silently loses work. ERR-2: deleting or expiring the session server-side does not stop an open socket from writing — auth is checked only at upgrade. On the safe side: no exploitable XSS (React escaping holds), clean API input validation, and healthy keyboard nav with visible focus rings.

Accessibility is the sharpest "verify the claim" result: Lighthouse rates the key pages 95–100, but axe on the same pages plus interactive states finds 2 Critical + 3 Serious rule violations — a role="tree" sidebar without treeitems, aria-expanded on a non-widget editor div, and 25 contrast failures on /my-week — all of which the generous score and the repo's own critical-only specs miss. On a Treasury (*.treasury.gov) app that's a Section-508 gap. Final tally across 7 categories: 62 findings — 4 Critical, 21 High, 25 Medium, 12 Low. audit/AUDIT_REPORT.md assembled.

2026-07-27 · Group B (api-perf → db-query) — complete

Six endpoints benchmarked at 10/25/50 connections — 16,200 requests, zero errors. Raw latencies are healthy at this volume (worst P95 94.5 ms on /api/issues), but the benchmark itself surfaced the second Critical: the first load-test run got 511,872 responses and every single one was a 429 — the production rate limiter allows 100 req/min per IP while one page view costs 4–16 requests, and the client never retries a 429, so throttled writes just vanish. The whole benchmark had to be re-architected around the limiter to get valid numbers at all.

db-query then captured 684 statements across six flows with Postgres logging (enabled, measured, reverted). The shape of the data: auth middleware is 52–94% of every flow's queries (a session-row write on every read), 61% of DB time is plan-not-execute, and the week dashboard has a genuine 25-query N+1. DB-1 — the migration bug from the gate — was independently reproduced on a throwaway database and confirmed Critical: the 31 skipped files contain every ALTER TABLE and backfill the schema has.

2026-07-27 · Group A (type-safety · bundle · tests) — complete

The counts are done but the stories matter more. Type safety: 1,535 tracked violations, yet the real exposure is structural — the entire DB→HTTP path is implicitly any (707 untyped queries), and web's tsconfig silently dropped three strict flags the other packages inherit, hiding 102 latent errors. Bundle: 699.8 KB gzip total of which 85.9% is one 2.07 MB entry chunk — no route splitting anywhere, so the login page downloads the admin dashboard and the entire editor stack (35.5% of the chunk by itself).

Tests ran 3× (~9 min per e2e pass, 1,471 tests): 1,446 clean, but 13 web unit tests are failing and nothing ever runs them — there is no CI in the repo at all. Retries masked a test that failed its first attempt in every single run, 68 e2e tests can pass without asserting anything (two of them are the only XSS and authorization checks), and the documented pnpm test flow TRUNCATEs whatever database it's pointed at — the audit had to build a separate DB to survive it.
